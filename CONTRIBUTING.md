# Reporting bugs and requesting features

Bug reports and feature requests are welcome. They are collected as issues in
this repository:

- **Found a bug?** Open a [bug report](https://github.com/Stumm-Consulting-GmbH/em4me/issues/new?template=bug_report.yml).
- **Missing something?** Open a [feature request](https://github.com/Stumm-Consulting-GmbH/em4me/issues/new?template=feature_request.yml).

Before opening a new issue, please check the
[existing issues](https://github.com/Stumm-Consulting-GmbH/em4me/issues)
to see whether the same bug or wish has already been reported.

## What a good bug report contains

- The EM4me version (shown in the About dialog) and your operating system.
- The steps to reproduce the problem, as precisely as you can.
- What you expected to happen, and what happened instead.
- If it helps: a small Markdown file that shows the problem, or a screenshot.

## What a good feature request contains

- The task you are trying to do, in your own words.
- How you do it today, and what gets in the way.
- If you have one: a concrete idea of how it could work.

## Security vulnerabilities

Please do not report security vulnerabilities as issues. Use the private
reporting described in [SECURITY.md](./SECURITY.md) instead.
